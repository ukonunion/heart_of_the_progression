# Проверки Heart of the Progression 0.6.0

7 октября 2026. Windows 11, Forge 1.20.1-47.4.23, Java 17.0.20.1, Gradle 8.8.

- Сборка и 13 JUnit-тестов прошли. Все 26 GameTest прошли без сторонних модов и с полным набором. Прежние сценарии стамины, искры, требований, опыта, сохранения и жизненного цикла сохранены; четыре новых сценария проверяют дерево, миграцию и магическую защиту.
- Очки дерева выдаются отдельно на уровнях 5, 10, 15…; повторное повышение после административного понижения уровня не даёт награду второй раз. Старые достигнутые пороги учитываются один раз. NBT сохраняет изученные навыки, остаток очков и отметку выданных наград; Clone сохраняет эти поля. Миграция 9/1 → 10/10 сохраняет оплаченные повышения, а превышение максимума возвращает очками атрибутов.
- ParCool: все 23 штатных изучаемых действия из родных JSON-деревьев с зависимостями; заблокирован прямой запуск неизученного действия. Настоящее нативное обучение расходует RPG-очко вместо ванильного XP, меняет capability и открывает действие. Родной экран дерева заменяется нашим.
- Epic Fight: все 23 зарегистрированных книжных навыка, нативное изучение и назначение в совместимый слот. Старые книги и поддельный родной C2S-запрос не обходят дерево. Штатные книжные пулы и mob GLM отключены; финальный Forge loot filter убирает также книги из добавленных пулов. Игровой GameTest проверяет настоящий итоговый список лута, а не только отдельный предикат. Категории, недопустимые слоты и задержка замены проверяются сервером; открытый экран обновляет кнопки после окончания задержки.
- Магическая защита проверена через настоящий `LivingHurtEvent`: при Интеллекте 20 десять единиц magic-урона превращаются в 9.6. Iron’s magic tags, включая огненные заклинания, относятся к магической защите; обычное горение, lightning/freeze и ванильный poison сохраняют свои категории.
- Четыре сценария настоящего клиента с integrated server: первое открытие меню и полный перезапуск отдельно без сторонних модов и с полным набором. Реальные C2S/S2C-запросы учат ParCool и Epic Fight, списывают очки и назначают нативные навыки. Пустые RPG/Iron’s вкладки, отключённые отсутствующие моды, GUI Scale 2/3, начало атрибутов 10 и загрузка оригинальной иконки 16×16 проверены. Маркеры: `RPG_TREE_CLIENT_INITIAL PASSED`, `RPG_TREE_CLIENT_RELOGIN PASSED`.
- Миграция конфигурации проверена при открытии копии старого разработческого мира: файл сохраняет стартовые значения 10/10, пороги слотов 11…37 и версию правил 4. Миграция откладывается до первого серверного тика: запись нескольких отдельных ConfigValue в Loading могла вызвать частичное восстановление старых значений файловым watcher.
- 20 скриншотов меню/дерева/эффекта. 19600 непрозрачных пикселей спрайтов сверены с оригинальным атласом: полный обычный и наведённый спрайт в меню, восемь недоступных кнопок, свободная от tooltip часть наведённой кнопки навыка. Атлас 64×128 содержит три области 40×40, а прозрачные поля не растягиваются. Три новых PNG совпадают с предоставленными файлами побайтово; остальные PNG совпадают с 0.5.3. HUD этой версии не менялся.
- Готовый reobfuscated JAR загружен до `Done` и штатно остановлен с кодом 0 в пяти режимах: standalone, только ParCool, только Epic Fight, Iron’s с зависимостями, полный набор. В JAR 18 PNG, полный refmap; тесты и сторонние моды не включены. Инкрементальная Java-компиляция отключена, поскольку она могла удалить агрегированный Mixin refmap при изменении класса без mixin-аннотаций; сборка JAR дополнительно проверяет наличие refmap.

Проверены ParCool **4.0.1.1**, Epic Fight **20.14.17**, Iron’s **1.20.1-3.16.3**, Curios **5.14.1**, GeckoLib **4.8.4**, Player Animator **1.0.2-rc1+1.20**, Iron’s Lib **1.20.1-2.2.0**. Сторонние моды устанавливаются отдельно. Пользовательские игровые миры не изменялись: клиент работал только с собственными копиями разработческих миров.

В Iron’s 3.16.3 есть две прежние ошибки сторонних loot JSON: `crypt_loot` (не указан name ссылки на таблицу) и `citadel_tomes` (`set_written_book_pages`, отсутствующий в 1.20.1). Они присутствуют также в логах прежних релизов, не мешают серверу запуститься и не исправлялись этим обновлением. Проверка не охватывает каждый сторонний аддон и длительную нагрузку большого модпака.

Логи и XML: `docs/verification/v150-*`. `v150-refmap-before-fix.log` намеренно сохраняет падение промежуточной сборки без refmap; игровые логи окончательной сборки не содержат ошибок mixin-инъекций, обращения к ненагруженному конфигу или `Missing RPG player capability`. Скриншоты: `docs/screenshots/standalone-v150/` и `combined-v150/`. Пиксели: `v150-pixel-verification.json`, исходный скрипт `verify_tree_v150.py` (Python + Pillow, пути рабочего окружения).

Повторение: `gradlew test build runGameTestServer`; полный набор — `runGameTestServer -Pirons -Pepicfight -Pparcool`. Клиент: `runClient -PtreeSmoke -PsmokeWorld=<копия_мира>`, затем ещё один запуск с `-PtreeRelogin`. Тестовый мир должен существовать заранее. Параметр `-PironsLibVersion=1.20.1-2.2.0` выбирает соответствующую библиотеку; для офлайн-проверки использован локальный Maven-репозиторий. Тестовые классы лежат в `gametest` и исключены из игрового JAR.

# История проверок 0.5.3

6 октября 2026. Forge 1.20.1-47.4.23, Java 17.0.20.1.

Старый код 0.5.2 воспроизвёл ошибку пользователя: `removedplayerticksandrevival failed! Missing RPG player capability`. В регрессионном тесте удаление `KILLED` отключает capability до события `PlayerTickEvent.END`. После исправления этот тест проходит и проверяет отсутствие сброса данных, перемещения брони, обработки поздних запросов, безопасный временный `invalidateCaps/reviveCaps` и сохранение прогресса при Clone.

- Сборка и 13 JUnit-тестов прошли.
- Все 22 GameTest прошли в standalone и с полным набором модов. Для полного набора использованы версии из присланного лога: Epic Fight 20.14.17, ParCool 4.0.1.1, Iron’s 3.16.3, Curios 5.14.1, GeckoLib 4.8.4, Player Animator 1.0.2-rc1+1.20, Iron’s Lib 1.20.1-2.2.0.
- Два запуска настоящего клиента с integrated server: смерть → `KILLED` → недоступная capability → пакет возрождения → сохранённые уровень/XP/очки/атрибуты/искра; сохранение в состоянии смерти → полный перезапуск клиента → вход мёртвым персонажем → повторное возрождение. Маркеры: `RPG_LIFECYCLE_DEATH PASSED`, `RPG_LIFECYCLE_RELOGIN PASSED`.
- Production JAR загружен до `Done` и штатно остановлен с кодом 0 без сторонних модов, с Iron’s и с полным набором. В production проверен Iron’s Lib 2.2.0.
- Все assets совпадают с 0.5.2. В JAR 17 PNG; тестовые классы исключены. UI/пиксельные проверки относятся к неизменившейся версии ресурсов 0.5.2 и ниже сохранены как история.

В реальном Clone обработчики сторонних модов могут снова вызвать `reviveCaps` на старом объекте после нашего обработчика. Поэтому реальный тест проверяет, что старый мёртвый/удалённый объект не получает ресурсные тики даже при доступном handle; отдельный GameTest проверяет корректное завершение именно нашего обработчика Clone.

Логи: `docs/verification/v143-*`. `v143-before-fix.log` намеренно содержит воспроизведённое падение старого кода. Остальные логи не содержат `Missing RPG player capability`. Тестовый клиент управляет только отдельной копией разработческого мира, не сохранением пользователя.

Для повторения: `gradlew runGameTestServer`; полный набор — `-Pirons -Pepicfight -Pparcool`. Клиентский сценарий — `runClient -PlifecycleSmoke -PsmokeWorld=<копия_мира>`, следующий запуск дополнительно `-PlifecycleRelogin`. Тестовый мир должен существовать заранее. `-PironsLibVersion=1.20.1-2.2.0` выбирает библиотеку из лога; при офлайн-проверке JAR пользователя подключён через локальный Maven-репозиторий. Тестовые классы расположены в `gametest` и не распространяются в игровом JAR.

XP: отдельные множители четырёх источников, правила ID/тегов, приоритет точного ID, нулевая награда. Настоящий FurnaceResultSlot проверен при частичном получении, пустом стеке после Shift-клика и повторном onTake: начисление ровно один раз. Настоящий костёр: placeFood, сохранение/загрузка UUID владельца, завершение cookTick, отсутствие повторной награды.

Iron’s: настоящие MagicData, атрибуты и FIREBOLT_SPELL. Native castSpell списывает RPG-ману один раз; штатная проверка заклинания видит общий запас и отказывает при нуле. Отдельное native восстановление отключено, RPG соблюдает задержку и скорость. Проверены addMana, отмена ChangeManaEvent, NaN, максимум, внешний модификатор экипировки, выключение адаптера и отсутствие вмешательства в ману мобов. В integrated client проверены настоящее заклинание на сервере, S2C остаток и чтение его ClientMagicData.getPlayerMana.

Epic Fight: native capability/predicate/consumer ресурса STAMINA, общий максимум/истощение, серверные возвраты, отсутствие второго восстановления. Native C2S дебет принят один раз, клиентское пополнение и NaN отклонены. ParCool: настоящее действие/пакет, предсказание/серверное подтверждение, общий запас с Epic Fight, отсутствие дублирующего HUD и стоимости sprint.

Меню: framebuffer при GUI Scale 2/3, реальные нажатия первого и шестого атрибута, оба состояния кнопок и максимальный уровень. Без Iron’s — три числовых показателя, с ним — четвёртая строка маны. Визуально проверены модель, надписи, рамки и отсутствие заполняемых полос здоровья/стамины. Все три PNG меню совпадают с оригиналами побайтово. HUD показывает ресурсы при расходе и скрывает после восстановления. Release JAR не содержит тесты и внешние моды.

## Воспроизведение

```powershell
.\gradlew.bat build runGameTestServer
.\gradlew.bat runGameTestServer -Pirons -Pepicfight -Pparcool
.\gradlew.bat runClient -Psmoke -PhudSmoke -PsmokeWorld=RPGSmokeStandalone
.\gradlew.bat runClient -Psmoke -PhudSmoke -Pirons -Pepicfight -Pparcool
```

GameTest использует отдельную папку run/gametests/<профиль> для каждого набора модов. Клиентские smoke-миры заранее создайте отдельно в run/saves: RPGSmokeStandalone без дополнительных модов, RPGSmoke с полным набором. Язык ru_ru в options.txt. Smoke меняет прогресс/предметы тестового персонажа; используйте только тестовые миры. Экран подтверждения экспериментального измерения Iron’s обрабатывается opt-in сценарием; резервное копирование выполняется через стандартный экран Minecraft, когда он появляется. `-PhudSmoke` добавляет 18 состояний HUD к `-Psmoke`. Без -Psmoke сценарий не запускается, в release JAR он не входит.

## Практические пределы

Будущие версии внешних API требуют повторной проверки; другие ветки адаптеры не включают. Два внешних аутентифицированных клиента, большой модпак и длительная нагрузка не проверялись. Требования предметов не охватывают нестандартные слоты Curios и действия, обходящие Forge-события. Опыт автоматических машин без игрока и костров с владельцем офлайн не назначается.

Официальный Iron’s 3.16.3 пишет ошибки разбора двух собственных loot tables (crypt_loot, citadel_tomes); эти файлы не входят в RPG. Проверки маны/заклинаний прошли. Dev-логи также содержат сообщения refmap, недоступных серверов проверки версий/Realms и cape-сервера Epic Fight. Логи текущей версии: docs/verification/v142-*. Прежние логи оставлены как история.
