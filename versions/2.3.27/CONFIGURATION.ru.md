# Конфиги Heart of the Progression 2.3.27

Главный файл: `rpgprogression-server.toml`.

По умолчанию в установленном NeoForge 21.1.256 используется `<папка сборки или сервера>/config/rpgprogression-server.toml`. В Prism откройте папку конкретной сборки Minecraft, затем `config`.

Для отдельного мира можно положить файл с тем же именем в `saves/<мир>/serverconfig/` (одиночная игра) или `<папка сервера>/<мир>/serverconfig/` (выделенный сервер). Такой файл имеет приоритет над общим `config/rpgprogression-server.toml`. Если в старом мире он уже есть, редактируйте именно его. Порядок проверен по исходникам установленного NeoForge и реальной загрузкой TOML из папки мира.

Файл создаётся после первого запуска мира с модом. Проще редактировать его при закрытом мире и затем открыть мир снова. Изменения также подхватываются наблюдателем серверного конфига; сервер пересылает действующие правила клиентам. Изменять клиентский конфиг для этих настроек не нужно. В выпуске приложены полные проверенные TOML: стандартный и отдельный пример настройки. Пример сам не применяется: это материал для редактирования или осознанной замены файла.

## Требования предметов и рабочих блоков

Раздел `[itemRequirements]` содержит шесть независимых списков:

| Ключ | Атрибут |
|---|---|
| `strength` | Сила |
| `endurance` | Выносливость |
| `agility` | Ловкость |
| `vitality` | Живучесть |
| `intelligence` | Интеллект |
| `spark_potential` | Потенциал искры |

Запись `namespace:item=число` назначает требование предмету, включая модовые. Для группы предметов используйте `#namespace:tag=число`. Порог — целое число 0–10000. ID можно посмотреть через расширенные подсказки Minecraft (F3+H). Если мод или тег отсутствует, запись просто не совпадёт ни с чем.

```toml
[itemRequirements]
useDefaultRequirements = true
strength = ["minecraft:diamond_sword=18", "minecraft:bow=13"]
endurance = ["minecraft:diamond_sword=12", "minecraft:netherite_sword=0"]
agility = []
vitality = ["minecraft:diamond_chestplate=30"]
intelligence = ["minecraft:brewing_stand=18"]
spark_potential = []
```

В примере алмазному мечу нужны Сила 18 и Выносливость 12, луку — Сила 13 и стандартная Ловкость 15, алмазному нагруднику — Живучесть 30 и стандартная Выносливость 20, зельеварке — Интеллект 18. Стандартная Выносливость незеритового меча снята. Другие предметы сохраняют прежние требования.

Совпавшее правило заменяет автоматическое требование только своего атрибута. Остальные атрибуты сохраняются. Значение 0 снимает этот атрибут. Среди нескольких совпавших пользовательских записей, включая теги, побеждает наибольшее значение: правило с нулём не отменит другое совпавшее положительное правило. Например, `endurance = ["#minecraft:swords=7"]` заменит стандартное требование Выносливости у всех предметов этого тега на 7.

`useDefaultRequirements = false` отключает автоматические требования материалов, снаряжения, рабочих станций и предметов Iron’s, но сохраняет условия из этих списков. Пустые списки при `true` используют текущий стандартный баланс 2.3.21, включая требования оружия и брони из REQUIREMENTS.ru.md. Сброс существующего конфига не нужен; пользовательские записи сохраняют свой приоритет. Заклинания имеют собственные правила ниже.

Те же значения используются для подсказок и серверных запретов: удары, добыча, использование, надевание и взаимодействие с поставленными рабочими блоками. Для блока указывайте ID его предмета. Требования появляются столбцом; выполненные условия скрываются по одному. Творческий режим и наблюдатель сохраняют прежнее исключение.

## Свитки и заклинания внутри книг Iron’s

```toml
[spellRequirements]
baseIntelligence = 10
intelligencePerManaUnit = 5
strength = ["irons_spellbooks:fireball=12"]
endurance = []
agility = []
vitality = []
intelligence = ["irons_spellbooks:fireball=18"]
spark_potential = []
```

Для положительной стоимости формула — baseIntelligence + intelligencePerManaUnit × преобразованная мана (1–8 единиц). По умолчанию 10 + 5 × мана: 15/20/25/30/35/40/45/50. Нулевая стоимость остаётся без автоматического условия. baseIntelligence меняет базовую часть; intelligencePerManaUnit меняет множитель, а 0 отключает всё автоматическое условие, включая базу. Итог ограничен 10000. Списки работают по точному ID заклинания, без тегов. Они могут заменить Интеллект или добавить любой из остальных пяти атрибутов. Ноль снимает соответствующий атрибут у одного заклинания. Пример выше требует для огненного шара Интеллект 18 и Силу 12 независимо от его уровня; остальные заклинания сохраняют формулу 10 + 5 × положительная мана.

Правила действуют и для свитка, и для заклинания внутри книги. Условия самого предмета книги или посоха из `[itemRequirements]` проверяются отдельно. Запись для общего предмета `irons_spellbooks:scroll` не отменяет собственные условия заклинаний: меняйте их в `[spellRequirements]`.

## Стоимость перемещений

```toml
[spark]
skintOpenMinimum = 25.0
skintTravelCost = 5.0
dimensionTravelCost = 25.0
```

`skintOpenMinimum` — минимум текущей искры для ручного открытия скинта. Открытие её не списывает; это не требование вместимости и не Потенциал искры. 0 отключает проверку, допустимы дроби до 1000000. Прибытие после оплаченного маршрута продолжает уже разрешённую сессию и не требует снова иметь 25. Мана не проверяется.

`skintTravelCost` — цена любого успешного перехода между скинтами, в одном или разных измерениях. `dimensionTravelCost` — цена обычного перехода между измерениями. Они не складываются. Допускаются 0 (бесплатно) и дробные числа, например 2.5; предел — 1000000. Меню показывает текущую цену скинта без лишнего `.0`. Сервер проверяет её перед вставанием и перед переносом, затем списывает один раз. Неудачные и отменённые переходы бесплатны. Если цену повысить во время вставания и искры уже не хватает, персонаж останется у исходного скинта. Творческие перемещения остаются бесплатными.

## Опыт для следующего уровня

```toml
[experience]
baseLevelXP = 500.0
levelXPCurve = "STAGED"
levelXPMultiplier = 1.011111111111111
customLevelXPFormula = "base * level ^ 2"
```

`baseLevelXP` — базовое значение, от 1 до 1000000000000. `levelXPCurve` выбирает формулу:

- `STAGED` — существующая кривая. При базе 500 переход с уровней 1/5/50/100 стоит 500/700/7000/41000 опыта.
- `EXPONENTIAL` — `base × multiplier^(level − 1)`; множитель задаётся `levelXPMultiplier`.
- `CUSTOM` — выражение из `customLevelXPFormula`.

Пример линейного роста:

```toml
[experience]
baseLevelXP = 250.0
levelXPCurve = "CUSTOM"
customLevelXPFormula = "base + (level - 1) * 125"
```

Переходы с уровней 1/2/3/4 потребуют 250/375/500/625 опыта. Ещё примеры: `base * level ^ 2` — квадратичная кривая; `base * multiplier ^ (level - 1)` — экспоненциальная; `base` — одинаковая стоимость на каждом уровне.

Переменные: `level` — текущий уровень (минимум 1), `base` — baseLevelXP, `multiplier` — levelXPMultiplier. Константы: `pi`, `e`. Разрешены `+ - * / % ^`, скобки и функции `min(a,b)`, `max(a,b)`, `pow(a,b)`, `abs(x)`, `sqrt(x)`, `floor(x)`, `ceil(x)`, `round(x)`, `log(x)` (натуральный логарифм), `exp(x)`, `clamp(x,min,max)`. Степень вычисляется справа налево, `-2^2` равно -4. Десятичные числа пишутся через точку. Выражения не исполняют код.

Результат округляется до ближайшего целого и ограничивается диапазоном 1–9000000000000000. Переполнение положительной стоимости достигает верхней границы. Неопределённое числовое значение возвращает стоимость STAGED на этом уровне. Синтаксически неверный конфиг исправляется штатной системой NeoForge; для ручного вызова предусмотрен безопасный резервный расчёт. Длина выражения — до 1024 символов, вложенность — до 32.

Формула определяет цену одного следующего уровня, а не суммарный опыт с первого уровня. Уже купленные атрибуты, уровень и остаток опыта не обнуляются. Снижение стоимости может сразу дать дополнительные уровни из накопленного остатка. Очень большие начисления на произвольной CUSTOM-кривой обрабатываются порциями на следующих тиках без потери опыта и без зависания сервера; одинаковая стоимость обрабатывается сразу.

## Заряженные мобы

Мод не назначает мобам имя «Заряженный скинтом» и не рисует количество HP. Их отличают частицы. Обычные имена боссов, бирки игроков и интерфейсы других модов сохраняются. В 2.3.13 подписи были только у проверочных экземпляров на снимках; в новой галерее они убраны.


Генерация скинтов в 2.3.17 задаётся ресурсами worldgen/structure_set и тегами биомов; их можно переопределить датапаком. Подробности и значения расстояния: STRUCTURES.ru.md. Существующие параметры требований, цен, опыта и ресурсов в этом выпуске не менялись.

## Торговля и новые группы предметов 2.3.22

```toml
[interactionRequirements]
villagerTradeIntelligence = 20
```

Минимум интеллекта для торговли с жителями и странствующими торговцами. 0 отключает условие, предел 10000. Оно действует отдельно от useDefaultRequirements, включая уже открытое меню и попытки забрать результат обычным или Shift-кликом. Предметы оплаты при отказе не расходуются.

Автоматические группы itemRequirements теперь включают редстоун (Интеллект 15 с исключениями), артефакты Relics (Интеллект 15) и эндер-сундук (Потенциал искры 20). useDefaultRequirements = false выключает эти автоматические условия вместе с остальными предметными правилами. Пользовательские ID/теги продолжают работать; например intelligence = ["minecraft:lever=0"] снимает условие рычага, spark_potential = ["minecraft:ender_chest=25"] меняет порог эндер-сундука. Список редстоуна можно расширять датапаком через тег rpgprogression:redstone_intelligence. Требования торговли и открытия скинта меняются своими параметрами выше.

В существующий конфиг автоматически добавятся недостающие новые ключи. Прежние пользовательские списки не сбрасываются. Новая база формулы свитков по умолчанию равна 10; для прежнего поведения 5 × мана задайте baseIntelligence = 0 при intelligencePerManaUnit = 5. При явном переопределении конкретного заклинания база не добавляется поверх указанного пользователем порога.

## Clavis

В серверном разделе `[attributes]` добавлен `clavisLifeSaveChancePerFiveAgility = 0.025`. Это вероятность за каждые полные 5 уровней Ловкости выше фиксированного уровня 10: `min(1, floor(max(0, Ловкость − 10) / 5) × коэффициент)`. Допустимые значения 0..1. Значение 0,025 даёт +2,5 п.п. за пятёрку; 0,05 — +5 п.п.; 0 полностью отключает бонус. Общая вероятность никогда не превышает 100%. Например, при обычном коэффициенте Ловкость 25 даёт 7,5%, 100 — 45%.

Коэффициент синхронизируется с сервера, подсказка Ловкости отражает действующее значение. Порог 10 не зависит от `startingAttributeValue`. При срабатывании бонуса защищаются жизнь мини-игры, включая последнюю, и текущее качество добычи. Оба эффекта используют один бросок шанса. При несрабатывании остаются обычные потеря жизни и штраф к качеству добычи. Clavis остаётся отдельным необязательным модом со своими зависимостями. Пакет не включает его JAR.

## Выпадающий RPG-опыт мобов

Все прежние параметры `[combatXP]` продолжают определять суммарную награду. С 2.3.26 она превращается в сущности `rpgprogression:progression_orb` и начисляется лишь при подборе. Нулевая награда не создаёт сущностей. Фиксированные параметры поведения: до 12 звёздочек на убийство, задержка подбора 20 тиков, притяжение в радиусе 16 блоков с ускорением до 0,018 и горизонтальной скоростью не больше 0,16 блока/тик, срок жизни 6000 активных тиков. Значение каждой сущности хранится как long вместе с возрастом и задержкой подбора; повторный подбор исключён, слияние не переполняет предел XP_LIMIT.

С 2.3.27 убийства в творческом режиме всегда создают награду. `creativeGainsXP` продолжает управлять подбором и начислением: при выключенной настройке творческие игроки не расходуют звёздочки. Зрители не собирают их. Остальные занятия и ванильные сферы опыта не изменены. Для клиента и сервера нужна одна версия 2.3.27, протокол 24.
