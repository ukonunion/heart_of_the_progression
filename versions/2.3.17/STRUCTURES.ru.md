# Генерация структур скинтов — 2.3.17

Авторские восемь файлов 7×3×7 включены без изменения байтов в `data/rpgprogression/structure/`. Скинты появляются выключенными и включаются первым ПКМ, как обычный новый блок.

| Шаблон | Размещение |
|---|---|
| skint_cave_1, skint_cave_2 | Сухие пещеры обычного мира, ниже поверхности, ориентировочно Y −56…60 |
| skint_main_base | Остальные биомы обычного мира |
| skint_main_sand | Пустыни и пляжи |
| skint_main_red_sand | Мезы / badlands; добавляемые красные пустыни включайте в тег skint_red_sand |
| skint_main_mossy | Болота и джунгли, включая мангровые и бамбуковые варианты |
| skint_nether | Внутри Незера, на сухом полу примерно Y 33…116; не на бедроковой крыше |
| skint_end | На островах Энда при наличии основания, без площадок над пустотой |

Теги NeoForge `c:is_desert`, `c:is_beach`, `c:is_badlands`, `c:is_swamp`, `c:is_jungle` обеспечивают выбор для ванильных и совместимых модовых биомов. При пересечении тегов приоритет: красный песок → песок → мох → обычный вариант. Неизвестные биомы обычного мира получают main_base. Для новых красных пустынь и иных нестандартных биомов добавьте их ID в нужный тег `rpgprogression:has_structure/skint_red_sand`, `skint_sand` или `skint_mossy` через датапак.

Все шесть вариантов обычного мира входят в **один** набор размещения: поверхностные и пещерные площадки не создаются независимыми сетками рядом друг с другом. У Незера и Энда свои наборы с тем же интервалом. Поля JSON:

```json
"placement": {
  "type": "minecraft:random_spread",
  "spacing": 48,
  "separation": 32,
  "salt": 193726517,
  "spread_type": "triangular"
}
```

48 чанков = 768 блоков; разброс внутри ячейки задаёт ориентир 500–1000 блоков между соседними площадками. Минимальное расстояние между кандидатами по общей сетке — 528 блоков, поиск подходящего места внутри чанка может сдвигать центры ещё на 4 блока в сторону. Неподходящий рельеф, жидкость в пещере, недостаток свободного места или пустота Энда могут пропустить ячейку, поэтому жёсткой верхней границы 1000 блоков нет. Соседние измерения независимо выбирают места.

Генератор ищет площадку в девяти местах внутри выбранного чанка и проверяет весь размер 7×7, свободную высоту и опору. Допускается небольшое выравнивание основания; крутые склоны пропускаются. Воздух авторского шаблона освобождает место в пещере. На дне водоёмов вода остаётся в пустых местах, скинт и совместимые блоки заполняются водой.

Определения находятся в `data/rpgprogression/worldgen/structure/`, общие интервалы — в `worldgen/structure_set/skints_overworld.json`, `skints_nether.json`, `skints_end.json`. Для изменения частоты переопределите соответствующий JSON датапаком, сохраняя namespace и salt; `spacing` должен быть больше `separation`. Это настройки генерации мира, отдельные от серверного TOML баланса. Изменения действуют в новых чанках.

Для проверки вручную доступны `/place structure rpgprogression:skint_main_base` и остальные имена из таблицы. Команда ищет подходящее место с учётом биома и местности; принудительное размещение самого шаблона: `/place template rpgprogression:skint_main_base`. Последняя команда не соблюдает частоту и правила естественного размещения.

## Новые постройки

Постройте структуру в Java 1.21.1, выделите её структурным блоком `/give @s minecraft:structure_block`, сохраните под именем `rpgprogression:имя` и пришлите `saves/<мир>/generated/rpgprogression/structures/имя.nbt`. При имени без namespace ищите в `generated/minecraft/structures`. Укажите биомы, измерение и частоту. Новый скинт в шаблоне сохраняйте выключенным. Обычный структурный блок сохраняет до 48 блоков по каждой оси; большие постройки можно разделить на части.

Существующие области сохранения не перезаписываются. Для естественного появления откройте новые чанки; старые точки и личные открытия сохраняются.
