# Проверки Heart of the Progression 0.2.0

Дата: 6 октября 2026. Windows 11, JDK 17.0.20.1, Gradle 8.8, Minecraft 1.20.1, Forge 47.4.23. Совместимость: официальный ParCool 1.20.1-4.0.1.1.

## Выполненные проверки

- `build`: успешно; **4 JUnit-теста**, включая каждый порог инвентаря от 0 до 100 Выносливости.
- `runGameTestServer` без ParCool: **15/15 GameTest**.
- `runGameTestServer -Pparcool`: **15/15 GameTest** с реальным ParCool и применёнными optional Mixins.
- `runClient -Psmoke -PsmokeWorld=RPGSmokeStandalone`: **RPG_CLIENT_SMOKE PASSED**, обычный игрок и integrated server без ParCool.
- `runClient -Pparcool -Psmoke`: **RPG_CLIENT_SMOKE PASSED**, обычный игрок и integrated server с ParCool.
- Production dedicated server (официальный installer, готовый reobfuscated JAR в `mods`): проверены запуск с ParCool и запуск без ParCool до `Done`, штатное завершение через `stop`, exit code 0. Сервер использует loopback 127.0.0.1 и online-mode.

## Что проверяют сценарии

Базовые 14 серверных сценариев проверяют XP, распределение очков и серверную валидацию, модификаторы, стамину и истощение, атаки и добычу, рыбалку, фактическую дистанцию бега, защиту от повторной добычи поставленных блоков, отменённый break, creative/spectator, обе сетки крафта, Quick Charge и реальное натяжение/выстрел лука, NBT и clone после смерти, все виды кликов/drag/shift/слияния/Forge item handlers и безопасный перенос предметов.

Проверки обновлены под **стартовые атрибуты 9**. Цикл по Выносливости 9…36 подтверждает открытие 0…27 слотов по одному. Старый стандартный конфиг 1.0 в тестовом мире автоматически мигрировал на новые значения.

Дополнительный `optionalParCoolStamina` проверяет:

- Общий максимум и текущее значение RPG/ParCool.
- Настоящий Wall Jump списывает 50×0.1 = 5 единиц на сервере.
- Настоящий Fast Run за 20 рабочих тиков списывает 4 единицы; обычный sprint не списывается повторно.
- Расход RPG виден через stamina API ParCool; изменение Выносливости меняет общий максимум.
- Снимок с клиента ParCool со значением 9999 не перезаписывает серверный RPG-запас.
- Истощение прекращает продолжающееся действие и запрещает новый старт; порог восстановления общий.
- Отключение совместимости возвращает независимое поведение.
- В отсутствие ParCool обращения к bridge и его Mixins не выполняются.

Клиентский сценарий проверяет S2C-синхронизацию, **нажатие текстурной кнопки с пересчётом координат мыши**, серверную трату одного очка и обратную синхронизацию. При ParCool дополнительно проверяется подключение `RPGLocalStamina`, скрытие второй полоски, предсказание расхода и настоящий native ParCool C2S action packet с последующим RPG S2C-ответом: на сервере списывается ровно одна стоимость.

## Визуальная проверка

Снимки получены из framebuffer запущенного Minecraft, не являются макетами. Проверены русское меню при GUI Scale 2 и 3, замки инвентаря (один дополнительный слот открыт при Выносливости 10), HUD стамины. Снимки: `docs/screenshots/`.

Фон и четыре пользовательские иконки в ресурсах совпадают с оригиналами побайтово. Прозрачные заготовки и все PNG включены в JAR и отдельный ресурс-пак. Пакет `gametest` и классы ParCool не включены в распространяемый RPG JAR.

## Воспроизведение

```powershell
.\gradlew.bat build runGameTestServer
.\gradlew.bat runGameTestServer -Pparcool
```

Для клиентского smoke создайте отдельный тестовый мир `run/saves/RPGSmoke` (можно скопировать `run/world` после GameTest), задайте `lang:ru_ru` в `run/options.txt`. Тест перезаписывает характеристики, поэтому не используйте свой игровой мир.

```powershell
.\gradlew.bat runClient -Pparcool -Psmoke
.\gradlew.bat runClient -Psmoke -PsmokeWorld=RPGSmokeStandalone
```

Для второго варианта предварительно создайте отдельный мир с именем RPGSmokeStandalone без ParCool. Опция `-PsmokeWorld=NAME` позволяет выбрать другой тестовый мир. Обычный `runClient` без `-Psmoke` не выполняет сценарий. Все тестовые классы исключены из release JAR.

## Границы проверки

Два внешних аутентифицированных клиента одновременно не подключались; длительная нагрузка и большие модпаки не проверялись. Проверена конкретная версия ParCool 4.0.1.1. Ветка 3.x отключает адаптер; совместимость с будущими изменениями 4.x требует повторной проверки. Не добавлялись фиктивные Удача, Перегрузка или Угасание искры из референса: таких механик в RPG нет.

Результаты 0.2.0 находятся в `docs/verification/v110-*.log`; более старые журналы оставлены как история проверок 0.1.0.
