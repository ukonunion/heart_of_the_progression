# Проверки Heart of the Progression 0.4.0

6 октября 2026. Windows 11, Java 17.0.20.1, Gradle 8.8, Minecraft 1.20.1, Forge 47.4.23.

## Результаты

- Сборка `build` и 9 JUnit-тестов: успешно.
- `runGameTestServer` без дополнительных модов: 20/20 сценариев.
- `runGameTestServer -Pirons -Pepicfight -Pparcool`: 20/20 сценариев.
- Клиент с integrated server без дополнительных модов и с полным набором: `RPG_CLIENT_SMOKE PASSED` в обоих вариантах.
- Готовый reobfuscated JAR на обычном dedicated server: `Done`, затем штатный `stop`, код 0 в трёх вариантах — RPG отдельно, RPG + Iron’s с зависимостями, RPG + Iron’s + Epic Fight + ParCool. Использованы отдельные миры, loopback 127.0.0.1, online-mode.

Проверены Iron’s Spells ’n Spellbooks **1.20.1-3.16.3**, GeckoLib **4.8.4**, Curios **5.14.1+1.20.1**, Player Animator **1.0.2-rc1+1.20**, Iron’s Lib **1.20.1-2.1.0**, Epic Fight **20.14.17**, ParCool **4.0.1.1**.

## Проверенное поведение

Базовые сценарии покрывают XP/уровни/очки, характеристики, стамину и истощение, слоты/контейнеры/Forge item handlers, рецепты, лук/арбалет, защиты, NBT и смерть. Требования предметов проверены для всех шести атрибутов. Настройки в GameTest меняются в памяти: файловый watcher не может менять временные правила посреди проверки.

Искра: старт 25, потенциал 1, +5 ёмкости, полное восстановление за 24000 тиков на первом уровне и более быстрое заполнение большего резервуара на втором. Разрешение перехода не списывает ресурс; успешный переход стоит 25, недостаток блокирует его. Проверены смерть, финальные титры Края, сохранение дробных ресурсов и добавление новых полей старым персонажам. В реальном integrated server выполнены межпространственные ServerPlayer.teleportTo: переход за 25, отказ при пустом запасе, успешное возвращение после пополнения и синхронизация клиенту.

XP: отдельные множители четырёх источников, правила ID/тегов, приоритет точного ID, нулевая награда. Настоящий FurnaceResultSlot проверен при частичном получении, пустом стеке после Shift-клика и повторном onTake: начисление ровно один раз. Настоящий костёр: placeFood, сохранение/загрузка UUID владельца, завершение cookTick, отсутствие повторной награды.

Iron’s: настоящие MagicData, атрибуты и FIREBOLT_SPELL. Native castSpell списывает RPG-ману один раз; штатная проверка заклинания видит общий запас и отказывает при нуле. Отдельное native восстановление отключено, RPG соблюдает задержку и скорость. Проверены addMana, отмена ChangeManaEvent, NaN, максимум, внешний модификатор экипировки, выключение адаптера и отсутствие вмешательства в ману мобов. В integrated client проверены настоящее заклинание на сервере, S2C остаток и чтение его ClientMagicData.getPlayerMana.

Epic Fight: native capability/predicate/consumer ресурса STAMINA, общий максимум/истощение, серверные возвраты, отсутствие второго восстановления. Native C2S дебет принят один раз, клиентское пополнение и NaN отклонены. ParCool: настоящее действие/пакет, предсказание/серверное подтверждение, общий запас с Epic Fight, отсутствие дублирующего HUD и стоимости sprint.

Меню: framebuffer при GUI Scale 2/3, реальные нажатия первого и шестого атрибута, оба состояния кнопок и максимальный уровень. Без Iron’s — три числовых показателя, с ним — четвёртая строка маны. Визуально проверены модель, надписи, рамки и отсутствие заполняемых полос здоровья/стамины. Все три PNG совпадают с оригиналами побайтово. HUD показывает ресурсы при расходе и скрывает после восстановления. Release JAR не содержит тесты и внешние моды.

## Воспроизведение

```powershell
.\gradlew.bat build runGameTestServer
.\gradlew.bat runGameTestServer -Pirons -Pepicfight -Pparcool
.\gradlew.bat runClient -Psmoke -PsmokeWorld=RPGSmokeStandalone
.\gradlew.bat runClient -Psmoke -Pirons -Pepicfight -Pparcool
```

GameTest использует отдельную папку run/gametests/<профиль> для каждого набора модов. Клиентские smoke-миры заранее создайте отдельно в run/saves: RPGSmokeStandalone без дополнительных модов, RPGSmoke с полным набором. Язык ru_ru в options.txt. Smoke меняет прогресс/предметы тестового персонажа; используйте только тестовые миры. Экран подтверждения экспериментального измерения Iron’s обрабатывается opt-in сценарием; резервное копирование выполняется через стандартный экран Minecraft, когда он появляется. Без -Psmoke сценарий не запускается, в release JAR он не входит.

## Практические пределы

Будущие версии внешних API требуют повторной проверки; другие ветки адаптеры не включают. Два внешних аутентифицированных клиента, большой модпак и длительная нагрузка не проверялись. Требования предметов не охватывают нестандартные слоты Curios и действия, обходящие Forge-события. Опыт автоматических машин без игрока и костров с владельцем офлайн не назначается.

Официальный Iron’s 3.16.3 пишет ошибки разбора двух собственных loot tables (crypt_loot, citadel_tomes); эти файлы не входят в RPG. Проверки маны/заклинаний прошли. Dev-логи также содержат сообщения refmap, недоступных серверов проверки версий/Realms и cape-сервера Epic Fight. Логи релиза: docs/verification/v130-*. Прежние логи оставлены как история.
