# Проверки Heart of the Progression 0.3.0

6 октября 2026. Windows 11, Java 17.0.20.1, Gradle 8.8, Minecraft 1.20.1, Forge 47.4.23. Реальные официальные моды: Epic Fight 20.14.17 и ParCool 4.0.1.1.

## Результаты

- Сборка `build` и 6 JUnit-тестов: успешно.
- `runGameTestServer` без обоих дополнительных модов: 17/17 сценариев.
- `runGameTestServer -Pepicfight -Pparcool`: 17/17 сценариев.
- Клиент с integrated server без обоих модов: `RPG_CLIENT_SMOKE PASSED`.
- Клиент с integrated server и обоими модами: `RPG_CLIENT_SMOKE PASSED`.
- Готовый reobfuscated JAR на обычном dedicated server: запуск до `Done` и штатный `stop` с кодом 0 в трёх вариантах — RPG отдельно, RPG + Epic Fight, RPG + Epic Fight + ParCool. Использован loopback 127.0.0.1, online-mode.

## Проверенное поведение

Базовые сценарии проверяют RPG XP, очки/атрибуты, стамину, атаки/добычу, истощение, NBT/смерть, открытие по одному слоту на Выносливость, закрытые слоты/Forge item handlers, рецепты, лук/арбалет и сопротивления.

ParCool: настоящий Wall Jump и Fast Run, один расход на действие, общий максимум, запрет клиентского перезаписывания, общий порог истощения, выключение адаптера.

Epic Fight: его настоящие capability, predicate и consumer ресурса STAMINA. 3 единицы навыка расходуют 15 RPG; изменение Выносливости отражается в API; native serverTick не восстанавливает второй запас. Проверены истощение/восстановление, серверный возврат, выключение интеграции, совместный запас трёх модов. В клиентском сценарии вызывается настоящий LocalPlayerPatch.setStamina с native CPSetStamina и проверяется RPG S2C-ответ: один расход, отсутствие клиентской возможности пополнить запас или записать NaN. Стоимость обычной RPG-атаки сохраняется; дополнительные расходы навыков Epic Fight определяются его параметрами.

Требования предметов: все пять атрибутов, точный порог, сочетания правил и тегов, максимальный порог при пересечениях, отсутствие блокировки для неуказанных предметов. Forge-события проверяют запрет атаки без расхода стамины, правого клика, серверной добычи и возврат недоступной брони без потери. Unit-тесты проверяют формат правил и недопустимые значения.

Клиент: реальное нажатие кнопки меню с GUI-масштабированием, сетевое повышение атрибута, показ/скрытие стамины и XP, воздух и броня при использовании. Снимки из framebuffer Minecraft: меню при GUI Scale 2/3, максимальный уровень, инвентарь, спокойный и активный HUD. Модель смотрит прямо; подписи и рамки не перекрываются. Фон совпадает с оригиналом пользователя побайтово. JAR содержит только один PNG и не содержит классы тестов или встроенные копии Epic Fight/ParCool.

## Воспроизведение

```powershell
.\gradlew.bat build runGameTestServer
.\gradlew.bat runGameTestServer -Pepicfight -Pparcool
.\gradlew.bat runClient -Psmoke -PsmokeWorld=RPGSmokeStandalone
.\gradlew.bat runClient -Pepicfight -Pparcool -Psmoke
```

Для smoke нужны отдельные тестовые миры `run/saves/RPGSmokeStandalone` без дополнительных модов и `run/saves/RPGSmoke` с нужными модами. Их можно создать заранее обычным `runClient`; язык ru_ru задаётся в options.txt. Тест меняет характеристики, предметы, XP и временные требования, поэтому используйте только тестовые миры. `-PsmokeWorld=NAME` выбирает имя. Без `-Psmoke` сценарий не запускается. Тестовые классы исключены из release JAR.

## Ограничения проверки

Два внешних аутентифицированных клиента, большой модпак и длительная нагрузка не проверялись. Поддержка будущих версий Epic Fight 20.14.x/ParCool 4.x требует повторной проверки API; другие ветки не включают адаптеры. Curios и предметы, полностью обходящие стандартные Forge-события, не покрываются требованиями vanilla экипировки/использования.

В development-логах Forge возможны сообщения о refmap, отсутствующих классах необязательных cape-аддонов Epic Fight и Realms при запуске dev-профиля. При удалении модов из тестового мира Forge сообщает о недостающих registry mappings; GameTest завершился успешно. Это отделено от проверок production JAR. Логи текущей версии: `docs/verification/v120-*`. Старые v110-логи оставлены как история предыдущего релиза.
