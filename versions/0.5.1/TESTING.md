# Проверки Heart of the Progression 0.5.1

6 октября 2026. Windows 11, Java 17.0.20.1, Gradle 8.8, Minecraft 1.20.1, Forge 47.4.23.

## Результаты 0.5.1

- Сборка `build`, 11 JUnit-тестов: успешно; проверка заполнения дополнена для нечётной рабочей ширины 73 пикселя.
- Клиент с integrated server без дополнительных модов и с Iron’s + Epic Fight + ParCool: `RPG_CLIENT_SMOKE PASSED`. По 18 состояний HUD в каждом запуске, включая три новых: показатели в углу, лошадь с 60 максимальными HP и зарядом прыжка, снятие экипировки и выход из транспорта.
- Растровая проверка 36 скриншотов: симметрия заполнения, 36420 непрозрачных пикселей рамок/значков совпали с исправленными оригиналами. Броня, воздух, искра, мана, XP, три ряда HP лошади и заряд прыжка проверены в правом нижнем углу. Центральные HP/голод/стамина сохраняют координаты при появлении дополнительных показателей.
- Все 13 исправленных PNG HUD совпадают с оригиналами побайтово; для обычного яда использован исправленный файл `hp/hardcore/poison.png`. Соответствие путей: `docs/verification/v141-asset-map.json`.
- Production JAR прошёл запуск до `Done` и штатный `stop` с кодом 0 без модов, с Iron’s и с полным набором. JAR содержит 16 PNG и не содержит тестовых классов или внешних модов.

Скриншоты: `docs/screenshots/standalone-v141/` и `docs/screenshots/combined-v141/`. Логи, JUnit XML и результаты: `docs/verification/v141-*`. Скрипт проверки: `docs/verification/verify_hud_v141.py`, Python + Pillow; vanilla icons.png можно положить рядом со скриптом для проверки вне исходного workspace. Хардкорный флаг и заряд прыжка задаются временно на клиенте только в opt-in тесте; состояние мира не переводится в хардкор. Тестовая лошадь удаляется после сценария.

Изменений серверных игровых правил нет; 20 GameTest из 0.4.0 не запускались повторно. Старые результаты ниже относятся к соответствующим версиям. Скриншоты прошлых версий сохранены в их исходных архивах; архив 0.5.1 включает актуальные скриншоты.

## История проверок 0.5.0


- Сборка `build` и 11 JUnit-тестов: успешно. Два новых теста проверяют парное заполнение, границы/NaN и единственный выбор варианта эффекта/хардкора.
- Клиент с integrated server без дополнительных модов и с полным набором: `RPG_CLIENT_SMOKE PASSED` в обоих вариантах. Проверены существующие сценарии меню/совместимости и 15 новых состояний HUD в каждом запуске.
- Готовый reobfuscated JAR на dedicated server: `Done`, затем штатный `stop`, код 0 в трёх вариантах — RPG отдельно, RPG + Iron’s с зависимостями, RPG + Iron’s + Epic Fight + ParCool.
- Пиксельная проверка 30 скриншотов HUD: симметричное заполнение из центра, верный цвет, 30586 непрозрачных пикселей рамок/значков совпали с оригиналами. Все 13 PNG HUD и три PNG меню совпадают с файлами пользователя побайтово.
- Release JAR содержит 16 PNG и не содержит тестовые классы или внешние моды. Архивы исходников и ресурс-пака проверены на целостность; контрольные суммы записаны рядом с ними.

В клиентском тесте сервер задаёт настоящие эффекты и ресурсы, а клиент проверяет их синхронизацию и сохраняет framebuffer. Сценарии: половина/полный/пустой запас, поглощение, яд, иссушение, замерзание, эффект голода, несколько эффектов одновременно, пять хардкорных вариантов, снятие эффектов. При полном запасе стамина скрывается. В сценарии пустого запаса HP оставлено равным 1, чтобы персонаж оставался живым; голод и стамина равны 0.

При совпадении иссушения, яда и поглощения выбирается только иссушение. Снятие всех эффектов возвращает обычные HP и голод. Хардкорный флаг меняется временно только в клиентском тестовом объекте LevelData; сохранение мира не переводится в хардкор. Проверка растров читает исходные PNG и пиксели игровых скриншотов: учитывает полупрозрачные штрихи поверх линии и проверяет неизменность непрозрачных рамок/центральных значков. Половина запаса занимает одинаковые 19 пикселей по обе стороны центра.

Скриншоты: `docs/screenshots/standalone-v140/` и `docs/screenshots/combined-v140/`. Результаты: `docs/verification/v140-hud-raster.json`, `v140-TEST-*.xml`, `v140-client-*.log`, `v140-production-*.log`, `v140-build.log`. ## Проверенное поведение 0.4.0

Базовые сценарии покрывают XP/уровни/очки, характеристики, стамину и истощение, слоты/контейнеры/Forge item handlers, рецепты, лук/арбалет, защиты, NBT и смерть. Требования предметов проверены для всех шести атрибутов. Настройки в GameTest меняются в памяти: файловый watcher не может менять временные правила посреди проверки.

Искра: старт 25, потенциал 1, +5 ёмкости, полное восстановление за 24000 тиков на первом уровне и более быстрое заполнение большего резервуара на втором. Разрешение перехода не списывает ресурс; успешный переход стоит 25, недостаток блокирует его. Проверены смерть, финальные титры Края, сохранение дробных ресурсов и добавление новых полей старым персонажам. В реальном integrated server выполнены межпространственные ServerPlayer.teleportTo: переход за 25, отказ при пустом запасе, успешное возвращение после пополнения и синхронизация клиенту.

XP: отдельные множители четырёх источников, правила ID/тегов, приоритет точного ID, нулевая награда. Настоящий FurnaceResultSlot проверен при частичном получении, пустом стеке после Shift-клика и повторном onTake: начисление ровно один раз. Настоящий костёр: placeFood, сохранение/загрузка UUID владельца, завершение cookTick, отсутствие повторной награды.

Iron’s: настоящие MagicData, атрибуты и FIREBOLT_SPELL. Native castSpell списывает RPG-ману один раз; штатная проверка заклинания видит общий запас и отказывает при нуле. Отдельное native восстановление отключено, RPG соблюдает задержку и скорость. Проверены addMana, отмена ChangeManaEvent, NaN, максимум, внешний модификатор экипировки, выключение адаптера и отсутствие вмешательства в ману мобов. В integrated client проверены настоящее заклинание на сервере, S2C остаток и чтение его ClientMagicData.getPlayerMana.

Epic Fight: native capability/predicate/consumer ресурса STAMINA, общий максимум/истощение, серверные возвраты, отсутствие второго восстановления. Native C2S дебет принят один раз, клиентское пополнение и NaN отклонены. ParCool: настоящее действие/пакет, предсказание/серверное подтверждение, общий запас с Epic Fight, отсутствие дублирующего HUD и стоимости sprint.

Меню: framebuffer при GUI Scale 2/3, реальные нажатия первого и шестого атрибута, оба состояния кнопок и максимальный уровень. Без Iron’s — три числовых показателя, с ним — четвёртая строка маны. Визуально проверены модель, надписи, рамки и отсутствие заполняемых полос здоровья/стамины. Все три PNG меню совпадают с оригиналами побайтово. HUD показывает ресурсы при расходе и скрывает после восстановления. Release JAR не содержит тесты и внешние моды.

## Воспроизведение

```powershell
.\gradlew.bat build runGameTestServer
.\gradlew.bat runGameTestServer -Pirons -Pepicfight -Pparcool
.\gradlew.bat runClient -Psmoke -PhudSmoke -PsmokeWorld=RPGSmokeStandalone
.\gradlew.bat runClient -Psmoke -PhudSmoke -Pirons -Pepicfight -Pparcool
```

GameTest использует отдельную папку run/gametests/<профиль> для каждого набора модов. Клиентские smoke-миры заранее создайте отдельно в run/saves: RPGSmokeStandalone без дополнительных модов, RPGSmoke с полным набором. Язык ru_ru в options.txt. Smoke меняет прогресс/предметы тестового персонажа; используйте только тестовые миры. Экран подтверждения экспериментального измерения Iron’s обрабатывается opt-in сценарием; резервное копирование выполняется через стандартный экран Minecraft, когда он появляется. `-PhudSmoke` добавляет 18 состояний HUD к `-Psmoke`. Без -Psmoke сценарий не запускается, в release JAR он не входит.

## Практические пределы

Будущие версии внешних API требуют повторной проверки; другие ветки адаптеры не включают. Два внешних аутентифицированных клиента, большой модпак и длительная нагрузка не проверялись. Требования предметов не охватывают нестандартные слоты Curios и действия, обходящие Forge-события. Опыт автоматических машин без игрока и костров с владельцем офлайн не назначается.

Официальный Iron’s 3.16.3 пишет ошибки разбора двух собственных loot tables (crypt_loot, citadel_tomes); эти файлы не входят в RPG. Проверки маны/заклинаний прошли. Dev-логи также содержат сообщения refmap, недоступных серверов проверки версий/Realms и cape-сервера Epic Fight. Логи текущей версии: docs/verification/v141-*. Прежние логи оставлены как история.
