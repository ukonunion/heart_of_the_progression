После исправления этот тест проходит и проверяет отсутствие сброса данных, перемещения брони, обработки поздних запросов, безопасный временный `invalidateCaps/reviveCaps` и сохранение прогресса при Clone.

- Два запуска настоящего клиента с integrated server: смерть → `KILLED` → недоступная capability → пакет возрождения → сохранённые уровень/XP/очки/атрибуты/искра; сохранение в состоянии смерти → полный перезапуск клиента → вход мёртвым персонажем → повторное возрождение. В реальном Clone обработчики сторонних модов могут снова вызвать `reviveCaps` на старом объекте после нашего обработчика. Поэтому реальный тест проверяет, что старый мёртвый/удалённый объект не получает ресурсные тики даже при доступном handle; отдельный GameTest проверяет корректное завершение именно нашего обработчика Clone.

Логи: `docs/verification/v143-*`. `v143-before-fix.log` намеренно содержит воспроизведённое падение старого кода. Остальные логи не содержат `Missing RPG player capability`. Тестовый клиент управляет только отдельной копией разработческого мира, не сохранением пользователя.

Для повторения: `gradlew runGameTestServer`; полный набор — `-Pirons -Pepicfight -Pparcool`. Клиентский сценарий — `runClient -PlifecycleSmoke -PsmokeWorld=<копия_мира>`, следующий запуск дополнительно `-PlifecycleRelogin`. Тестовый мир должен существовать заранее. `-PironsLibVersion=1.20.1-2.2.0` выбирает библиотеку из лога; при офлайн-проверке JAR пользователя подключён через локальный Maven-репозиторий. Тестовые классы расположены в `gametest` и не распространяются в игровом JAR.

## Воспроизведение

```powershell
.\gradlew.bat build runGameTestServer
.\gradlew.bat runGameTestServer -Pirons -Pepicfight -Pparcool
.\gradlew.bat runClient -Psmoke -PhudSmoke -PsmokeWorld=RPGSmokeStandalone
.\gradlew.bat runClient -Psmoke -PhudSmoke -Pirons -Pepicfight -Pparcool
```

GameTest использует отдельную папку run/gametests/<профиль> для каждого набора модов. Клиентские smoke-миры заранее создайте отдельно в run/saves: RPGSmokeStandalone без дополнительных модов, RPGSmoke с полным набором. Язык ru_ru в options.txt. Smoke меняет прогресс/предметы тестового персонажа; используйте только тестовые миры. Экран подтверждения экспериментального измерения Iron’s обрабатывается opt-in сценарием; резервное копирование выполняется через стандартный экран Minecraft, когда он появляется. `-PhudSmoke` добавляет 18 состояний HUD к `-Psmoke`. Без -Psmoke сценарий не запускается, в release JAR он не входит.

## Практические пределы

Будущие версии внешних API требуют повторной проверки; другие ветки адаптеры не включают. Два внешних аутентифицированных клиента, большой модпак и длительная нагрузка не проверялись. Требования предметов не охватывают нестандартные слоты Curios и действия, обходящие Forge-события. Опыт автоматических машин без игрока и костров с владельцем офлайн не назначается.

Официальный Iron’s 3.16.3 пишет ошибки разбора двух собственных loot tables (crypt_loot, citadel_tomes); эти файлы не входят в RPG. Проверки маны/заклинаний прошли. Dev-логи также содержат сообщения refmap, недоступных серверов проверки версий/Realms и cape-сервера Epic Fight. Логи текущей версии: docs/verification/v142-*. Прежние логи оставлены как история.
